# 投标文件全文一致性校验

标书几百页里，同一关键信息出现几十次。只要有一处不一致，就可能废标。这个技能只做一件事：把这些点全找出来。

## 检查项

至少覆盖这些，用户指定了其他项则一并加入：

| 信息项 | 常见出错形态 |
|---|---|
| 公司全称 | 有限公司 / 股份有限公司；简称混用；分公司误当投标主体 |
| 项目名称 | 与招标文件标题不一致；漏写或错写标段名 |
| 招标编号 | 末位差一个字母或数字；年份、批次写错 |
| 投标报价 | **小写金额与大写中文金额不一致（最高频废标项）**；分项合计与总价不符；单价×数量≠合价；漏项、缺项或多报 |
| 最高限价 | 投标报价超出招标文件最高限价 / 招标控制价 / 最高投标限价（超出即出局，一票否决） |
| 投标有效期 | 投标函与商务表不一致 |
| 工期 | "90 天"与"100 个日历日"；工作日 vs 日历天 |
| 质保 / 维护期 | 商务承诺"5 年"，售后章节"3 年" |
| 资质证书有效期 | 到期日早于投标日或开标日 |
| 联系人及联系电话 | 多处不一致 |

> **报价大小写不一致是实测最高频的废标原因**：改报价时漏改了正文里某处数字。用户改过报价后，必须全文重搜该金额再交标。

## 流程

1. **提取锚点值。** 以最权威位置（报价汇总表、封面、投标函）为基准，记录每个信息项的基准值与出处。
2. **全文检索。** 对每个基准值及其变体做全文搜索（含数字、大写金额、编号、电话），列出所有出现位置。
3. **逐位置比对。** 记录任何偏离；一致的地方不列。
4. **专项复核报价。** 小写 ↔ 大写逐字对；分项合计 ↔ 总价逐项加；单价 × 数量 ↔ 合价逐行算；核对明细有无漏项、缺项、多报；并与招标文件**最高限价 / 招标控制价**比对——超出即出局，属一票否决。
5. **专项复核证书与有效期。** 所有证书、证明的到期日与投标日、交货期对比。
6. 输出表格，按潜在废标风险降序。

## 输出模板

| 信息项 | 基准值（权威位置） | 出现位置 1 | 出现位置 2 | 不一致内容 | 风险等级 |
|---|---|---|---|---|---|
| 投标报价 | 壹佰贰拾叁万肆仟元整 / ¥1,234,000.00（P3 投标函） | P47 报价汇总表 | P217 分项明细表 | P217 小写金额缺"整"且与 P47 分项合计相差 100 元 | 高 |
| 公司全称 | 华信科技有限公司（封面） | P88 承诺书 | P190 售后服务方案 | 两处写作"华信科技股份有限公司" | 高 |

要求：
- 每条**必须给出至少两个具体位置**（页码或章节），否则用户无法修正。
- 只报不一致，不列"一致的地方"。
- 末尾追加 `报价核对小结`：大小写是否一致、分项合计是否等于总价、是否存在单价数量合价错误。
- 末尾追加 `有效期核对小结`：所有证书到期日清单，标注早于投标日的项。

## 红线

- **数字错误必须双引号引用原文后再下结论。** 禁止只给结论不给原文。工程与财务数字错一字就是废标。
- **不要替用户决定改成哪个值。** 以招标文件要求或公司定稿为准；两边冲突就标"需人工确认"。
- **涉密与成本数据**（成本结构、内部底价、合作方信息）不要在会话外扩散；严肃项目建议本地化处理或脱敏后再传。

## 陷阱

- **只查封面和投标函会漏。** 错误通常藏在报价明细、偏离表、附表里。
- **大写金额的"万/元/整"位置与"零"的处理最容易错**，必须逐字对齐，不要看个大概。
- **电子版与纸质版不一致也算不一致。** 若用户说分两版制作，要分别校验并交叉比对。
- **别把 OCR 误识当成不一致。** 扫描件识别出的数字存疑时，标"需人工确认（可能为识别误差）"，不要直接判错。
- 全文很长时分模块处理，但**跨模块的信息项（如公司全称）必须全局汇总后再输出**，避免每个模块各报一次。
